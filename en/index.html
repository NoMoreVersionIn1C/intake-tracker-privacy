Who is responsible for the application

The service provider identified above is responsible for Intake Tracker's data processing. This policy covers the Android application with package com.recursivekatz.intaketracker and the compatible watch application with package com.recursivekatz.intaketracker.wear.

For privacy questions, contact intaketracker.support@proton.me.

Scope of this policy

This policy describes processing by Intake Tracker on the phone and watch, manual backups, Android platform backup, synchronization through Huawei Health and Wear Engine, and advertising services. Third-party providers process data under their own notices, which are linked below.

The current release has no Intake Tracker account, no developer-operated backend, no cloud synchronization of intake records, no first-party analytics upload, and no first-party crash-report upload. It performs no payment processing and has no contact, calendar, photo, or media access.

Data processed locally

The phone may locally store:

  • action name and category;
  • dosage and instructions;
  • schedule, weekdays, and Snooze options;
  • active and archived state;
  • Done, Snoozed, Skipped, and retracted response history;
  • technical reminder, backup, and watch-synchronization state.

The watch keeps a bounded local cache of nearby actions, one urgent reminder, unacknowledged responses, and technical synchronization cursors. This cache keeps nearby actions available while the phone is temporarily absent.

How the data is used

Local data is used to show schedules and history, deliver reminders, calculate Snooze and the next event, perform manual export and restore, and synchronize with a paired watch.

Intake data is not sent to advertising providers. Application code does not give Petal Ads Prime or Yandex Mobile Ads SDK 8.2.0 action names, schedules, response history, backup contents, or Wear Engine messages.

Retention and user controls

Local records remain on the device until the user edits them, replaces them by restoring a backup, clears application data, or uninstalls the application. Archiving retains a record and marks it as archived. A supported response retraction leaves a technical record needed to reconcile history.

The developer cannot remotely inspect or erase the local Intake Tracker database. Provider-side retention and deletion of advertising data are governed by the relevant provider's notice and procedures, not by Intake Tracker's local settings.

Backups and transfer

Manual export writes a JSON document only to a location selected by the user. After export, the user controls its storage, copying, sharing, and deletion. Import validates a selected document and then replaces supported local actions and history with its contents.

Automatic Android platform backup and device transfer are disabled by the application configuration. The application rules exclude every supported private-data domain from cloud backup and device transfer. Manual JSON export and import occur only after an explicit user action.

Watch synchronization

Huawei Health and Wear Engine carry a bounded set of schedules, reminders, and technical states to the paired watch. Responses and acknowledgements can travel back to the phone. The watch retains compact state intended for temporary use without the phone.

Wear Engine is paired-device transport, not the developer's cloud backend. See the official Wear Engine overview.

Advertising

Version 1.0.0 does not display advertising. Advertising ID availability remains subject to Android and device settings. In this release, Intake Tracker application code does not initialize Petal Ads Prime or Yandex Mobile Ads and does not issue an advertising request. Both SDKs remain packaged for possible activation in a future update; permissions and components contributed by a packaged SDK do not by themselves prove data collection or transfer.

Advertising providers may process IP address, network and carrier information, device and application identifiers, technical characteristics, ad display and interaction events, timing and frequency, security information, and errors as described in their notices.

The SIM country is read transiently only to order advertising-provider attempts. Intake Tracker does not persist the SIM value or attach it to an ad request in application code. It is not a precise-location measurement, and the application requests no Android location permission.

Permissions and system features

Notification permission allows reminders to be shown. Exact-alarm special access schedules reminders as close to the requested time as Android rules permit. Device boot, time, and time-zone events are used to restore local alarm registrations.

Internet access is required by advertising SDKs and related network services. Some device and package capabilities are contributed by Huawei, Wear Engine, and advertising dependencies. A declared package capability does not prove that every related data type is collected on every run.

Third-party providers

Third-party providers determine processing, retention, deletion, and rights procedures for data received by their services:

  • Huawei Petal Ads release and privacy guidance;
  • Huawei Wear Engine;
  • Yandex Mobile Ads Android data guidance;
  • Yandex Privacy Policy;
  • GitHub Privacy Statement.

This site is hosted on GitHub Pages. GitHub may process IP address and HTTP request metadata as the hosting provider. The policy site itself adds no application-owned analytics, advertisements, cookies, or third-party scripts.

Children

Intake Tracker is not directed to children under 13. A parent or guardian who believes a child provided information to an advertising provider may contact that provider and the privacy contact listed in this policy.

Your rights and choices

Users can edit and archive actions, retract supported history entries, create and import backups, clear application data, or uninstall the application. Android settings provide controls for notifications, exact alarms, Advertising ID, and device backup.

For data held by an advertising or platform provider, use the channels and settings identified in that provider's notice. The developer has no remote access to local records and cannot perform deletion on a third-party provider's servers on its behalf.

Policy changes

If data processing changes materially, this policy and its effective date will be updated before or with the relevant application release. The current version is published at this address.

Contact

Questions about Intake Tracker's data handling and data-rights requests can be sent to intaketracker.support@proton.me. For data processed by a third-party provider, also use the provider's official channels listed under “Third-party providers.”
